# Lender site report — layout (pre-sprint design)

Brief 03 deliverable: *"Plain-language explanation of the main drivers a lender can review."*
Reader: a loan officer or credit committee member, not an engineer. One A4 page per site, PollPower design system (CMA-submittal style: gradient top bar, Bebas title, mono labels).

Nothing below is generated yet. `[ ]` marks a value the sprint code fills in.

## Writing rules

- Lead with the number, then the range. No jargon: "80% range", never "P10/P90 quantiles", in body text.
- Every multiplier gets a plain reason with the observed input ("77 large buildings within 1 km").
- Say what the model does **not** know (e.g. "no anchor load such as a mill was detected").
- Round to what the evidence supports: one decimal for kWh/customer, whole numbers for site totals.
- Always show the test record (section 5) so the lender can judge the model, not just the site.

## Section 4 inputs (from the developer)

Proposed system size, tariff, capex, loan term. Defaults for the demo: KES 32/kWh tariff, and a system sized to the P50.

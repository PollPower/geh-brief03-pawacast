# Compiling `zk/record.compact`

Target toolchain: Midnight **Compact 0.22** (`compactc 0.30.0`, language 0.22.0,
runtime 0.15.0, ledger 4.0.2). Same compactc build used by
`PollPower/contracts` (EBT v8 + tariff-registry).

Not deployed. Preview deploy needs an explicit ask.

## Exact command

Run from the repo root. `compactc` must be the 0.30.0 build on your `PATH`
(or substitute the absolute path, e.g.
`~/.compact/versions/0.30.0/x86_64-unknown-linux-musl/compactc`).

```
mkdir -p zk/build
compactc zk/record.compact zk/build/
```

Expected: ~4 seconds wall time, no stderr output beyond
`Compiling 1 circuits:`. Build artifacts land under `zk/build/` (see
“Output” below).

## Toolchain pinning

The source declares `pragma language_version >= 0.16 && <= 0.22;` — identical
to the EBT v8 / tariff-registry convention. compactc 0.30.0 speaks language
0.22.0 so the pragma range admits it; older compactc builds inside the range
should also work provided they implement the specific 0.22 syntax used here
(`assert(cond, "msg")`, no top-level `const`, ledger-scratch accumulator).

If `compactc` isn’t installed, grab it from the Midnight toolchain installer
and verify with `compactc --version` (expect `0.30.0`) and
`compactc --language-version` (expect `0.22.0`).

## Output

`zk/build/` contains:

```
compiler/contract-info.json       circuit + witness manifest
contract/index.d.ts               TypeScript type definitions
contract/index.js                 compiled JS shim (importable)
contract/index.js.map             source map for the JS shim
keys/<circuit>.prover             proving key   (~2.1 MB — NOT committed)
keys/<circuit>.verifier           verifying key (~1.3 KB)
zkir/<circuit>.bzkir              zkir bytecode   (binary)
zkir/<circuit>.zkir               zkir text (human-readable instruction list)
```

A frozen manifest of these artifacts lives at `zk/build-manifest.txt`
(generated by `scripts/gen-build-manifest.sh` after a successful compile).
`zk/build/` itself is gitignored.

## Fixture harness

`zk/run-fixtures.mjs` is a minimal offline harness: it loads the compiled JS
shim and invokes `prove_published_sum_and_count` once per fixture in
`zk/fixtures/`, with the fixture’s witness values. It checks that the
circuit’s accept/reject outcome matches the fixture’s `expect` field. It does
**not** generate real proofs — it exercises the circuit’s assert/revert
logic end-to-end against the compiled TS/JS shim and the compact runtime.

Prerequisite: `@midnight-ntwrk/compact-runtime@0.15.0` must be resolvable.
On the sprint machine the simplest path is a symlink to the sibling
`PollPower/contracts/tariff-registry/node_modules`:

```
ln -sf ../../contracts/tariff-registry/node_modules zk/node_modules
cd zk
node run-fixtures.mjs
rm zk/node_modules
```

Expected output:

```
=== Fixture results ===
[PASS] n9_should_fail.json: expect=reject outcome=reject err="failed assert: N_BELOW_K_MIN"
[PASS] valid_n10.json: expect=accept outcome=accept
```

The symlink is a convenience, not committed. If you’d rather have a proper
`package.json` in `zk/`, add one with a single dependency on
`@midnight-ntwrk/compact-runtime@0.15.0` and run `npm install` there.

## k-anonymity floor

`record.compact` uses `K_MIN() = 25`. This is **higher** than
`pawacast/sharing/validate.py` `MIN_CUSTOMERS = 10`. The two are intentionally
unaligned at this commit — the circuit encodes the sprint policy requested
alongside the port; `validate.py` still reflects the pre-sprint design. Any
reconciliation (either lifting the Python floor to 25, or lowering the circuit
floor back to 10) is a separate repo change and is not performed here.

Fixtures were updated to the new floor: `valid_n10.json` now has n=25
(accept), `n9_should_fail.json` now has n=24 (reject with N_BELOW_K_MIN).
Filenames are preserved for history.

## Changes from the Compact 0.18 scaffold

The 0.18 draft used:

- `pragma language_version 0.18.0;`
- `export ledger {}` (empty ledger block)
- Top-level `const K_MIN: Uint<32> = 10;` etc.
- `assert cond;` statements
- `let mut acc: Uint<64> = 0;` for in-circuit mutable locals
- `return true;` from the circuit (returning Boolean)

Compact 0.22 (as emitted by compactc 0.30.0) rejects every one of those at
parse time. The 0.22 rewrite:

- Pragma widened to `>= 0.16 && <= 0.22` (matches contracts repo).
- `export ledger {}` dropped; replaced with two scratch ledger cells
  (`_proofSum`, `_proofIdx`) that are reset at the start of every circuit
  call (documented pattern used by tariff-registry’s `_actionLogClimb`).
- Top-level constants rewritten as `pure circuit K_MIN(): Uint<32>` /
  `pure circuit N_MAX(): Uint<32>` (EBT v8 pattern).
- All `assert cond;` → `assert(cond, "ERROR_LABEL");`.
- `let mut acc` removed; sum/index accumulation uses the scratch ledger cells.
- Arithmetic requires explicit narrowing (`(a + b) as Uint<64>`) — compactc
  reports the raw additive-type width otherwise.
- Circuit return type changed from `Boolean` to `[]` (unit) because the
  circuit now relies solely on asserts; the previous `return true` was
  reachable only when all asserts had already passed.

Semantics (sum/count equality + k-anonymity floor + padding-is-zero) are
preserved byte-for-byte.
